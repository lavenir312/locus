# Locus ｜原文精读器

把一本书做成**能回查原文**的精读笔记。四条原则各配一个机器能查的检查，不过门禁不许交付。

不是又一个"一键拆书"工具。它解决的是另一件事：**生成的笔记里，哪句话是作者说的、哪句是模型加的、哪句能翻回第几页——要能验。**

```
拆章建锚  →  逐块台账  →  点数封闭清单  →  写笔记  →  两遍回读  →  门禁  →  单册 HTML
```

## 为什么要有这个东西

开源社区不缺"把书变笔记"的项目。做这个之前，我拿同一章原文（11,022 字、87 段、27 条尾注）把五个方案各跑了一遍，只换它们的规范、不换模型：

| 方案 | 约束放在哪 | 强在哪 | 弱在哪 |
|---|---|---|---|
| 书籍蒸馏 | 成品指标 | 分层清楚，锚点足 | 整篇不引一句原文，用段号替代 |
| learn-from-materials | 过程 | 逐块台账＋双向映射＋十项强制校验 | 读者版太薄，术语无机器校验 |
| fastReader | 提示词纪律 | 最好读，一口气能看完 | 产出无锚点 |
| dsh-deepread | 输出格式 | 四档置信度最细 | 体例僵硬，不好读 |
| idlearn | 无 | 封闭清单覆盖最高 | 英文输出、零定位、尾注全丢 |

结论很直接：**差距不在模型，在于约束落在哪一层。** 提示词层面的纪律靠自觉，输出格式层面的纪律只保证格式，只有放在**过程**里——每块都要登记、每条结论都要回指、整合后分查错查漏两遍再来一次——才拦得住错。

这个工具把那套过程约束拆出来，补上五个方案都没有的一环：**术语的机器校验**。

顺带一个反直觉的实测结果：覆盖率最高的那份（idlearn，15/19）恰恰最不可信。**覆盖率不等于准确率**，这是四条原则必须交叉校验、而不能只看一个指标的理由。

## 四条原则

**原｜忠诚原文**
引号内逐字，一字不改；改写不加引号；省略用「……」标出，不得跨段拼接伪装成连续原文。每条结论标来源等级：`【原意】`作者明确主张／`【事实】`原文事实与数据／`【推断】`基于原文的推演／`【存疑】`原文无依据。结论挂段号，能翻回去。

**全｜完整详尽**
每个来源块登记状态（covered / no-content / unreadable / duplicate）并写理由，空块不许默默跳过。凡"三层定义""五个阶层""27 条尾注"，登记 expected 与 found，两数必须相等——不许用"等""等等"糊过去。原文没给的写"原文未提供"，不替它补。

**术｜用专业概念，不自造词**
术语用学界通用名。作者自己造的提法（如"士见官欺民"）标明是他的提法，不当学界通名用。术语首次出现给一句界定 + 出处段。`audit.py terms` 把术语回原文找，找不到、又不在通行术语表里的，判为疑似自造。

**易｜可读，不冗余**
一句话 → 一段话 → 正文，三层递进。连贯叙述，不写要点罗列。该解释的背景解释，该画的图画（结构、因果链、时间线、多方对照），一句话能说清的不画。同一意思不说两遍。

## 安装

```bash
git clone https://github.com/lavenir312/locus.git && cd locus
pip install markdown          # 只有最后生成 HTML 需要
```

六个脚本里五个只用标准库，只有 `build_html.py` 依赖 markdown。Python 3.8+。

## 快速开始

**1. 拆章建锚**

```bash
python scripts/extract.py 某本书.epub --out work/
```

支持 epub / txt / md / html。产出 `work/NNN.md`，每段带 `[chNNN:pMMM]` 锚点，以及 `work/manifest.json`（章标题、字数、段数）。

> 默认**不合并**碎章，保证章号与原书目录一一对应。合并会让后面的锚点全部漂移。

**2. 算账排批（别跳过这步）**

```bash
python scripts/plan.py --src work/ --notes out/
```

它会告诉你：要写几章、每章按篇幅该用哪一档、分几批、哪几章太大该独占一批、哪些章已经有了可以跳过。已经写好的章自动剔除，所以这个命令可以随时重跑，是续写的入口。

一个 41 万字的书，空手开工和先算账的差别是 15 批和 73 个单元。

**3. 写笔记**

笔记文件名以三位章号开头（如 `012_作者_篇名.md`），便于与原文对上。结构见 `templates/note.md`，台账字段见 `templates/ledger.md`。要点：每个块要么进 claims / closedLists，要么进 blocks 标 `no-content` 并写理由。

**段落锚点要在初稿就标。** 每个判断句末带 `(pMMM)`，不要留到后补——后补等于把原文再读一遍，这一项返工的成本可以抵上半本书。

**4. 核验**

```bash
python scripts/audit.py all --note note.md --src work/012.md
```

三项：引文是否逐字、术语是否自造、锚点是否指向真实存在的段落。

**5. 门禁**

```bash
python scripts/gate.py --note note.md --ledger ledger.json --src work/012.md
```

十四条，分属四原则。不过不许交付，退出码非 0。锚点覆盖默认要求 30%；写的是提要级（800–1200 字）就用 `--min-cover 0.15` 明说，不要靠堆锚点凑数——那会把同一段反复引用，唯一段数并不会变。

**6. 批量核验**

```bash
python scripts/batch_audit.py --notes out/ --src work/ --json report.json
```

一本书几十章时用这个。跨章文件（总论、纲要）会自动识别：引文在全书范围核，锚点按各自章号校验。

**7. 出成品**

```bash
# 单册：通读、分享
python scripts/build_html.py --notes out/ --src work/ --title "书名" --out 书名_精读.html

# 分册：按笔记子目录（部）各出一册，打开快
python scripts/build_html.py --notes out/ --src work/ --title "书名" --out 分册/ --split part
```

单文件自包含：侧栏目录、全文搜索、点任意 `(pMMM)` 右侧滑出原文段落、mermaid 懒渲染。**无脚本也能读**——全书连续排版，目录是原生锚点跳转，JS 只做增强。拆册时每册只嵌入本册用到的原文，没有正文章节的目录（规格、台账）自动跳过。

## 规模与精度分档

动手前先定档。全本逐章精读的成本约等于"章数 × 每章字数"，不分档就是把钱花在不需要的地方。

| 档 | 每章字数 | 什么时候用 |
|---|---|---|
| 索引级 | 200–400 | 只要全书地图与关键引文 |
| 提要级 | 800–1,200 | 全书完整覆盖、每章可查，不追求论证复原 |
| 标准级 | 1,500–2,500 | 主力档，复原作者的论证链 |
| 精读级 | 4,000+ | 只有枢纽章值得（总论、分水岭章） |

混用是常态，但**必须在成品里标明每章档位**，否则读者会把提要当结论用。

## 一份笔记长什么样

`examples/` 里有一份能跑通的完整示例（自撰材料，不引自任何出版物）：

```bash
cd examples
python ../scripts/extract.py demo.txt --out work/
python ../scripts/audit.py all --note 000_demo_note.md --src work/000.md
python ../scripts/gate.py --note 000_demo_note.md --ledger 000_demo_ledger.json --src work/000.md
# → 14/14 通过 → 准入交付
```

## 实测记录

在一本 88 章、55.6 万字的中文论著上跑完整本（正文 73 章）：

- 引文 **764 条**，逐字命中 755 条，逐段核对过的省略节选 9 条，**对不上 0 条**
- 锚点 **2008 处**，全部指向真实存在的段落
- 笔记 13.1 万字，对原文 49.3 万字的压缩比 26.6%

同一批书稿里，逐块点数还抓出了几十处原书自身的不一致——同一篇文章的两条尾注引了不同年份的版本；同一段里前后用词不一致；某年发生的事被引在该刊创刊号出版之前。**这类问题只有逐条点数才看得见，摘要型工具不会去找，因为它的流程里没有"点数"这一步。**

### 这套东西花多少钱

同一本书的完整账单，可查到的部分：**256 分、1317 次模型调用、5.4 小时**。拆开看：

| 在干什么 | 调用 | 积分 | 产出 |
|---|---|---|---|
| 派子单元写笔记 | 13 次派单 | 约 105 | 13 万字，73 章全部 |
| 主会话反复跑脚本、验证、重建 | 138 次 Bash | 约 150 | 0 篇笔记 |

单次扣费中位数只有 0.14 分，钱是被次数乘以"每次背着的上下文长度"吃掉的，不是被字数吃掉的。所以这个仓库里最值钱的不是核验脚本，是 `plan.py`——它让你在开工前就知道要分几批，而不是写到一半发现一章派了一个单元。

同一轮里最贵的一笔错误：31 章写完了才想起来补段落锚点。补锚点要重读原文，那一项的成本等于把半本书再读一遍。现在这条要求在 `gate.py` 里由 AR4 把关，初稿漏了就过不了门禁。

## 门禁自己也会判错

这比结果重要，写在这里当提醒：**写门禁的脚本自己会误判，不看就下结论等于用错误的尺子量东西。**

实测中遇到过的四次：

1. 把笔记头部的书名与章标题当成引文，判"对不上"。修法：只分析第一个二级标题之后的正文。
2. 把加粗的整句当术语候选。修法：加粗候选限 2–10 字且不含句读。
3. 用「……」跨段省略的引文被判成改写。修法：按省略号切段逐段核对，全段对上判 `spliced`，单列不罚。
4. 把 mermaid 的 `flowchart LR` 里的 `LR` 当成英文缩写术语。修法：抽术语前剥掉代码块。

还有一次是门禁判对了、笔记错了：术语把两个词连写成一个新词，原文里并没有这个连写，两个词是对立的。改回原文写法才通过——**术语该跟原文，不该自己发明组合。**

所以：任何一次门禁结果，出数后都要抽三到五条回原文验。

## 局限

- **不替你想论点。** 它保证"你说的每句话都能回查"，不保证你说得对。
- **覆盖率不等于质量。** 段落覆盖率高只说明触得广，不说明读得深。
- **依赖原文质量。** EPUB 转换的噪声（占位行、错段的图注）会原样进锚点，`extract.py` 只做保守清理。
- **台账是重活。** 逐块登记的开销不小，章数多时建议只对主力章建完整台账，其余用 `batch_audit.py` 做引文与锚点核验，并在报告里如实说明这一项是近似。
- **mermaid 走 CDN。** 离线时图显示为源码，正文不受影响。

## 机制来源

四条原则不是凭空定的，各自的机制来自这些项目的具体文件，逐条对应见 `references/sources.md`：

- **dsh-deepread**（xiehuan123）——四档置信度的定义方式
- **learn-from-materials**（dmoshehun-prog）——逐块覆盖台账、双向映射、十项强制校验、术语大全规则、三级递进讲解、图表四条语义约束
- **fastReader / 咀华**（pf-sjtu）——把"原文说了的"与"评析"切成两部分的写法
- **书籍蒸馏** —— L1/L2/L3 分层
- **idlearn**（diomir0）——反面教材：中间层提示词只有一句 "Summarize concisely"，27 条尾注在最终摘要里全部消失。压缩层不设约束，细节一定丢。

本工具只做取舍与合并，争议时以各原仓库规则为准。

**借鉴的是设计思路，不是代码。** 本仓库六个脚本与上述四个 GitHub 项目抓取到的 13,015 行代码逐行比对，重合 12 行，全是 `argparse` 与 `if __name__ == '__main__'` 这类样板，业务逻辑零重合。各项目的许可证状况、署名要求、以及两个「无许可证」项目的处理方式，都写在 [`NOTICE.md`](NOTICE.md) 里。
